# PQ-NFT-USG Glossary
Comprehensive list of all **acronyms, initialisms, and key technical phrases** used throughout this conversation (March 2026).
| Term / Acronym              | Full Form / Definition |
|-----------------------------|------------------------|
| **Arweave**                 | Permanent, decentralized storage network (permaweb) used as immutable backup for NFT metadata and media. |
| **CAM**                     | Control Account Manager (Earned Value Management role; the Manufacturing Productivity Engineer may transition into this). |
| **CDK**                     | Chain Development Kit (Polygon’s toolkit for building custom zk-rollups and zkEVM chains). |
| **CISA**                    | Cybersecurity and Infrastructure Security Agency (U.S. government agency providing PQ migration guidance). |
| **Coq**                     | Interactive theorem prover / formal proof assistant used for verifying smart-contract and ZK invariants. |
| **DoD**                     | U.S. Department of Defense (one of the primary USG stakeholders for official communications). |
| **ERC-721 / ERC-1155**      | Ethereum standard for non-fungible tokens (NFTs); ERC-721 is single-token, ERC-1155 is multi-token. |
| **ERC-4337**                | Ethereum standard for account abstraction (used for PQ-native wallet signatures). |
| **EVM**                     | Ethereum Virtual Machine (base execution environment for Ethereum and EVM-compatible chains). |
| **FedRAMP**                 | Federal Risk and Authorization Management Program (U.S. government cloud-security compliance framework). |
| **FIPS 203**                | NIST standard for ML-KEM (post-quantum key encapsulation mechanism). |
| **FIPS 204**                | NIST standard for ML-DSA (post-quantum digital signature algorithm, primary). |
| **FIPS 205**                | NIST standard for SLH-DSA (stateless hash-based post-quantum signature algorithm, fallback). |
| **FunC**                    | Functional programming language used to write smart contracts on TON (Telegram Open Network). |
| **HSMs**                    | Hardware Security Modules (physical devices for secure key generation and storage, especially PQ keys). |
| **ICD**                     | Interface Control Document (systems-engineering artifact defining how cryptographic payload interacts with chain-specific layers). |
| **IPFS**                    | InterPlanetary File System (content-addressed decentralized storage for NFT TokenURI). |
| **Lean 4**                  | Modern proof assistant / programming language used for formal verification of circuits and contracts. |
| **leanVM**                  | Ethereum Foundation’s ultra-minimal 5-instruction RISC-V zkVM optimized for hash-based PQ proof aggregation (target 2026–2027). |
| **liboqs**                  | Open Quantum Safe library – reference implementation of NIST post-quantum algorithms (FIPS 203/204/205). |
| **MVI**                     | Modular Verifier Interface (design pattern allowing seamless swap between SP1/RISC Zero today and native leanVM tomorrow). |
| **ML-DSA**                  | Module-Lattice-based Digital Signature Algorithm (FIPS 204). |
| **ML-KEM**                  | Module-Lattice-based Key Encapsulation Mechanism (FIPS 203). |
| **NSA**                     | National Security Agency (provides PQ migration guidance alongside CISA). |
| **On-Chain**                | Data or logic that is permanently stored and executed directly on the blockchain (vs. off-chain). |
| **PDR**                     | Preliminary Design Review (formal systems-engineering gate at the end of Phase 1). |
| **Poseidon2**               | Arithmetic-friendly hash function optimized for zero-knowledge circuits (used instead of SHA-3 inside zkVM). |
| **PQ**                      | Post-Quantum (cryptography resistant to quantum computers). |
| **RISC-V**                  | Open-source instruction-set architecture used by leanVM and most modern zkVMs. |
| **RISC Zero / SP1**         | Production-grade RISC-V zkVM implementations used today as bridge until native leanVM lands. |
| **SEMP**                    | Systems Engineering Management Plan (governs the entire IPT). |
| **SLH-DSA**                 | Stateless Hash-based Digital Signature Algorithm (FIPS 205). |
| **SNARK**                   | Succinct Non-interactive ARgument of Knowledge (general ZK proof family; we use STARK variant). |
| **STARK / zk-STARK**        | Scalable Transparent ARgument of Knowledge (transparent, no trusted setup, hash-based ZK proof system). |
| **TEP-62 / TEP-74**         | TON NFT standards (equivalent to ERC-721/1155 on Telegram Open Network). |
| **TON**                     | Telegram Open Network (high-throughput, low-cost blockchain evaluated as parallel deployment option). |
| **TRL**                     | Technology Readiness Level (NASA/DoD metric used in leanVM and PQ assessments). |
| **TVM**                     | TON Virtual Machine (execution environment for FunC contracts). |
| **USG**                     | United States Government (primary stakeholder for the protocol). |
| **zk / ZK**                 | Zero-Knowledge (cryptographic proof that a statement is true without revealing underlying data). |
| **zkVM**                    | Zero-Knowledge Virtual Machine (executes arbitrary code inside a ZK proof). |
